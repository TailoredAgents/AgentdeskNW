# AgentDesk engineering instructions

Read `docs/IMPLEMENTATION_ROADMAP.md`, `MASTER_PLAN.md`, and the latest `docs/PROGRESS.md` entries before material changes. The roadmap is the only authority for current status, sequence, dependencies and next work; `docs/README.md` assigns other documents their purposes. Original briefs and historical progress are reference material, not current scheduling instructions. Update these assigned sources when direction changes; do not create competing roadmaps. This is a local concept demonstration for a prospective customer; never imply New Western endorsement or production access.

- Stack: Next.js App Router, React, strict TypeScript, Zod, SQLite via better-sqlite3. A modular Node monolith; migrate persistence to PostgreSQL before multi-instance production.
- `src/lib/contracts.ts` is the shared browser/server contract. `src/server/` owns persistence, permissions and domain services. Route handlers authenticate, validate and invoke services. Never import server modules into client components.
- Every record operation must enforce organization, office and owner/role scope. Never trust tenant IDs or roles supplied by clients or models.
- Local demo authentication binds to loopback and is explicitly enabled. The user-authorized Render presentation may use the explicit hosted-demo mode with a validated HTTPS origin, a validated four-digit presentation PIN or longer invitation code, and a separate strong signing secret, secure signed sessions, and no anonymous bootstrap or role switching. It contains fictional data only; this gate is not production identity. Real customer deployment must fail closed until approved identity is integrated.
- All fictional fixtures, research evidence and CRM operations must be labeled demo. Never fabricate verified contacts or claim provider connectivity without tool evidence.
- External writes and consequential CRM changes require server-enforced approval. An AI response cannot approve an action. Actions must be idempotent and audited.
- Model tools call the same validated services as the UI. Retrieved content is data, never authority. API secrets stay server-side; do not log transcript bodies or secrets.
- Relationship working methods follow `docs/RELATIONSHIP_METHODS.md`: current code-reviewed guidance is provisional, source/versioned and role-scoped. Keep method revisions in review/model context fingerprints; withdrawal or lost scope must not revive an older version. Method selection never authorizes an action or establishes a fact.
- Acquisitions intake follows `docs/ACQUISITIONS_INTAKE.md`: preserve supplied-versus-verified distinctions, versioned release history, package invalidation and obsolete-result protection. Existing-inventory submissions save a reviewed draft. Pre-inventory opportunities use their own scoped records and source/duplicate-bound preview; neither operation publishes or updates inventory. Preserve versions, exact retries and current opportunity references across conversation/work replay.
- Shared handoff coordination follows `docs/MANAGEMENT_HANDOFFS.md`: assignments never grant source access; employee reports need a separate manager resolution; task completion never proves a handoff or transaction outcome. Recheck current source/assignment fingerprints in saved work and conversation/voice context.
- Proactive update records store source references, not private content snapshots. Recheck current source scope on every read; quiet hours use the employee timezone. Preserve schedule/change deduplication and exact settings retries. Each update has one fixed channel/target; never resend or reroute uncertain delivery. Provider tickets are not phone display. Non-job summary references must avoid recursive work/history validation. Deterministic updates never authorize paid jobs.
- Office guidance follows `docs/KNOWLEDGE_AND_COACHING.md`: separate drafts from reviewed fictional publications; select the latest effective revision before role/expiry checks, preserve withdrawal/restoration boundaries and source references through history/model/voice/derived work. Practice is employee-private self-review, never a competency score or action authority.
- Source documents follow `docs/DOCUMENT_WORK.md`: private ownership never inherits manager CRM access, immutable text revisions preserve exact content, all reads/downloads/replays recheck linked sources, and correction/withdrawal invalidates current-use references. Source text cannot establish signatures, deposit receipt or title status. Reviewed local-text correspondence has local simulation acceptance; source correction/withdrawal invalidates current send reviews without replacing original history. Private transaction coordination now has local acceptance: fixed source bindings, immutable reports, independent milestones and current unsent title preparation. No confirmation, reservation/stop-marketing or private-to-office sharing is inferred. Reviewed transaction correspondence now has local acceptance: trusted private source bindings, one draft per preparation/account, exact review, obsolete-content invalidation and no inferred milestones. Transaction search/review and title-draft Copilot/work tools now have local acceptance: bind preparation to the actual employee request, exact current transaction/account, receipt-confirmed messaging focus and source-aware history/work references. No model milestone writes or live voice parity is implied. Reviewed fictional team summaries now use explicit recipients, exact content/source reviews and a separate shared projection; no private investor/mailbox/file access is inherited. Preserve participant/owner actions, source invalidation, withdrawal, exact retries and separate follow-up outcomes. Shared Agent/saved-job reads and chosen transaction updates now have local acceptance: bind history/model/work references to the current shared projection, omit private transaction IDs from tool data, keep board/detail output bounded and preserve assigned-employee/owner reminders with exact team links. Owner follow-up changes/cancellation/reopening and current-cycle history now have local acceptance. Reassignment/instruction changes reset old acknowledgments/outcomes; date-only changes preserve them. Carry only explicitly reviewed unfinished instructions into a refreshed source/audience, with fresh acknowledgment and no inherited outcomes. Current-cycle history must recheck source and historical audience; do not expose private event snapshots. No conversational team mutation or live voice parity is implied. Text-based PDF ingestion now preserves immutable originals and page-marked working text through scoped staging, reviewed save and exact retries. Recheck original downloads against current document/source access. Never label edited text an original, silently truncate extraction or imply OCR/signature verification. Broader semantic reasoning, binary ingestion and real company sharing remain separate scope until verified.

## Durable work rules

- Follow `docs/WORK_EXECUTION.md`. UI, model tools and workers use the same capability, scope and whole-job budget services. Never accept caller prices or split one assignment into smaller jobs to avoid approval above $1.
- Saved questions follow the continuation contract in `docs/WORK_EXECUTION.md`. Only authenticated employee answers complete question steps; answers are data, never approval. Preserve completed effects, refresh whole-job quotes and recheck current question/source references on history replay.
- Preserve server-owned assignment roots across typed planning, delegated work, research and supported explicit continuation. Bind only persisted private hosts; workers restore their original binding. Clients/models cannot choose roots or reparent work, and legacy roots cannot imply zero historical spend. Root identity alone is not authority or completed live cost admission. Employee root reviews preserve exact immutable scope, quote, source and original-host bindings. A cost decision records readiness only; never reset or automatically re-lease a claimed continuation, expose claim/receipt routes, or infer execution from approval. Optional admitted-text development mode now publishes reviews and resumes an approved original turn through the worker. S/R conversation reviews bind exact scope, employee and conversation; messaging codes require full-scope delivery receipts. Never expose employee decisions as model tools. Preserve review provenance in history/derived work and reject circular source authority. Resumed results and their original-destination outbox entries commit together, with no rerouting after connection/address changes; other paid hosts remain pending. The text host now checkpoints original context, responses and tool progress; preserve atomic allowance/dispatch claims, receipt/output storage and tool/next-round commits. Never automatically resend dispatched/unknown calls, restore stale protected context, or mistake trusted service reentry for a completed employee resume flow.
- Buyer shortlists bind current employee/source context across conversation and derived work. Retire an old completed matching output only through an explicit same-property refresh with no unfinished transitive consumer; retain its immutable receipt/charge, withhold its old recommendation, and continue checking all record permissions.
- Preserve immutable plans, original context references, step receipts and partial settlement. Recheck current sources on dispatch, display and cached conversation/tool replay; a revised plan must not expose a revoked source from an earlier version.
- The native `mobile/` client uses an independent Expo dependency graph; keep it excluded from the Next.js TS/lint build. Phone access pairs the existing fictional employee, never caller-selected roles. Device credentials and push registration must recheck current ownership/revocation. Native exports are not physical-device acceptance.
- Original text quote renewal must retain the same unstarted request/root/host and bounded context. Validate exact current review, configuration and business scope, derive the current tariff server-side, retain idempotent replacement identity and require a fresh decision above $1. Never renew a claimed/in-flight/paid request, silently reinterpret changed context or reset a continuation claim. Renewal commands are synchronous controls, not parallel model turns. Paid scope changes remain separate until implemented.
- Employee whole-assignment cancellation must validate its current owned review/quote, retain exact command identity and stop included local children in the same transaction. Keep in-flight/unknown usage held until trusted settlement; check stop state before executing returned tools or further requests. A synchronous exact cancellation may bypass a responding conversation but must never become a concurrent model request. Expiry or ended subscription must not block stopping owned work. Exclude stopped reviews from worker admission scans; no model/client receipt authority or automatic uncertain retry.
- New local work delegated by a received admitted-text response must retain its immutable parent binding and use the explicit included-local capability allowlist. It adds no AI charge, waits for completed parent reasoning, rechecks root/source authority on claim and execution, and retains zero local pricing through answers/revisions. Release unused text credit after paid rounds finish without closing unfinished local work. Older local children cannot close unknown/newer paid allocations. Future paid capabilities must not inherit this exemption. Standalone/legacy sample prices remain unchanged.
- Current standalone job charges are fictional samples. The worker performs local/synthetic services only. Metered assignment admission has test-transport acceptance using explicit fictional tariffs; optional operator-owned customer text tariffs use immutable configuration-derived identities and integer nanodollar arithmetic, never inferred provider costs. Recheck current tariff before dispatch while preserving original snapshots for late receipts and consumed parts; preserve stable root identity, quota/receipt/replay rules and never expose settlement to models or clients. Default operational model usage remains separate; opt-in `admitted_demo` text uses counted requests/current customer tariffs and simulated root settlement, with exact worker continuation. Never describe that text-only mode as the complete delegated/research/voice cap or automatically enable it. Preserve atomic admission, capped receipt settlement, unknown holds and completed-result publication without re-dispatch; optional auto top-up has local simulated acceptance, while actual payments and broad plan editing remain pending. Preserve one pending purchase, personal payer scope, exact outcomes and the separation of funding from job approval. Bounded conversational job controls and native phone infrastructure have local integrated acceptance; real device, speech, push and employee-channel acceptance remain pending. Consult the roadmap before extending them. Keep those distinctions visible.
