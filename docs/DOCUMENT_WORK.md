# Source documents and transaction work

This is the domain contract for the C3/C4 document extension. [IMPLEMENTATION_ROADMAP.md](IMPLEMENTATION_ROADMAP.md) remains the only scheduling/status authority. **Private text documents, reviewed local-text correspondence and private transaction coordination accepted locally, October 31, 2026.** Real provider retrieval, actual delivery and company-approved title/payment procedures remain deferred.

## Usable document foundation

Start with private, versioned text documents that employees can read, correct and reuse across desktop and mobile. Desktop can import a bounded UTF-8 text file; either interface can paste/edit fictional document contents. This gives the application actual content instead of treating an attachment filename as evidence. It does not parse PDF images, verify a signature, confirm a deposit or obtain an absent provider attachment.

Each document has a title, file name, purpose, source label/date, optional permitted property/investor references and exact content. These are employee-supplied records, explicitly fictional and unverified. Document text is data, never an instruction or action authority. Private ownership is independent of manager CRM access. A property/investor reference must remain accessible on every read, save, download and replay. Binding the source records at creation prevents a revision from silently moving a document to a different relationship or deal.

Content revisions are immutable; correction creates a new revision. A current-use reference binds document identity/version/content digest and current authorized source context. Withdrawal stops current use; original private history is retained only while the employee still has source access. Shared work and eventual attachment reviews must recheck the exact reference before use; no fallback to an older revision. A read/download is not approval to share it.

UI edits preserve their original base version. An unknown save outcome may only retry its original payload. Newer server revisions do not silently overwrite unsaved changes or adopt a new write version. A changed/revoked source removes protected content. Navigation and unsaved discard remain explicit. Downloads use authenticated private routes and attachment disposition, never public file URLs.

Track employee-reported milestones separately from external confirmation; retain who reported each fact, when and its supporting revision. ## Acceptance requirements

- Private account, organization/office/role and source access on every path, including replay and historical content.
- Actual text content and stable digest survive save/read/download and process restart; original revisions remain immutable.
- Correction, withdrawal or source changes invalidate a prepared reference; stale writes cannot overwrite newer content.
- Unknown outcomes recover once; no duplicate documents/revisions or lost unsaved edits across surfaces.
- Desktop/mobile content continuity, readable source labels, guarded navigation and explicit missing-file behavior.
- Full regression, isolated HTTP checks, migration-copy preservation and updated roadmap evidence before claiming acceptance.

Text-based PDF ingestion and extraction provenance now have local acceptance in the extension below. OCR, other binary formats, mailbox attachment retrieval, real document sharing/transfer, deeper semantic document reasoning and actual transaction package delivery remain unfinished. This text-content foundation must not be presented as all document handling completed.

## Shared follow-up changes and current-cycle history

The coordination owner can change an active follow-up's responsible teammate, instruction and/or due date with a reason. An assignee/instruction change resets acknowledgment and outcome; a date-only change preserves the existing acknowledgment and report. A no-op, unavailable assignee or past date is rejected. Canceling stops active counts/reminders and retains the earlier report as history, never as a resolved outcome. Resolved/canceled tasks require explicit reopening with a current assignment, date and reason; all prior acknowledgment/report/resolution/cancellation fields reset. Every action is version-bound, scoped, audited and exactly retryable. Team membership alone or manager role grants no owner authority, and the prior assignee cannot act after reassignment.

`GET /transactions/team/:teamId/tasks/:taskId/history` exposes only changed snapshots of that task in the current source/generation, up to 100 latest changes. It requires current shared access and source validity. Historical event audiences are checked again; private transaction/contact/file contents and whole event records are never returned. Source correction, withdrawal or lost membership withholds history. Earlier cycles remain in immutable audit storage, not displayed as current work. Both interfaces show the same history and exact before/after decisions, retain the original version while editing, and clear stale history/reviews on refresh. Optional carry fields preserve legacy omitted-field request hashes. This does not transfer coordination ownership, update private milestones, send correspondence or add conversation mutation authority.


## Text-based PDF import and preserved originals

Migration 037 adds scoped pending imports and immutable original files. Desktop Documents accepts a PDF up to 2 MB / 40 pages, extracts text locally with pinned `unpdf` 1.6.2 and presents a review before document save. The original filename, byte length, SHA-256, parser identity, page count and empty-page list remain separate from the working `.txt` revision. Page markers preserve extraction location; they do not establish reading order, table fidelity or completeness. No model, provider or wallet charge is involved.

Parsing runs in a separate process with no inherited application credentials, a 128 MB JavaScript heap limit and a 15-second termination deadline. Each web process allows two concurrent parsers. It supplies bytes, never a remote file URL, disables evaluation/system fonts/image decoding and rejects password-protected, malformed, wholly empty or over-limit files. Working text retains the existing 32,000-character / 64 KB bound; overflow is rejected rather than silently truncated. Mixed empty pages receive an explicit incomplete-extraction warning. Scanned pages require a checked transcription; no OCR, signature, deposit or title verification is performed. This is bounded text extraction, not full PDF semantic/layout interpretation.

`POST /documents/import` accepts a narrowly bounded JSON upload; other API requests retain their smaller limit. Request streams are counted in bytes while reading. A preview belongs only to the current employee, expires after thirty minutes and does not create a document. At most six uncommitted previews are retained per employee; expired previews are purged on that employee's next import. Explicit discard removes the staging copy. Membership/entitlement are checked both before and after parsing and again at commit. Unknown extraction responses can leave a temporary preview until expiry; retry does not create a source document. Exact document-save retries reuse the existing receipt even after the staging row is consumed.

An explicit save atomically commits the selected original, working revision and receipt. Original storage is capped at 50 MB per employee in this demonstration. Later text corrections inherit the unchanged source and are labeled edited; a replacement PDF keeps earlier originals with their historical revisions. Provenance comes only from the extraction service, not client-supplied metadata. Original reads and exact replay recheck current private ownership and linked-source access. A historical original remains readable after withdrawal or subscription end while source access remains valid. `GET /documents/:id/original?revision=N` returns an authenticated, noncached attachment, never an inline/public viewer.

Desktop/native display the same original provenance and corrected working text. Document polling allows an in-flight refresh to finish instead of repeatedly invalidating a slow initial load. Native can inspect and correct the saved extract, but phone picking/original download is not implemented yet. Current correspondence and title preparation use the explicitly named `.txt` extract; this extension does not transfer or simulate delivery of the original PDF. Natural-language document reasoning, OCR, broader formats and provider attachment transfer remain open. Official extraction library reference: [UnPDF](https://github.com/unjs/unpdf).


## Source-aware Copilot and saved review

Typed Copilot now exposes three read-only tools shared by web, native typed/dictated requests and configured employee messaging: `document_search`, `document_read` and `document_review`. Search uses literal words in current private metadata/working text and returns at most twelve metadata results, not an analysis. Reads return up to four lossless 1,200-character working-text sections with title/revision/section citations and a next-section pointer. These numbered sections are shared with the desktop and native document readers; they are not inferred PDF pages. Reviewed extraction provenance and missing-page/corrected-text cautions remain visible.

Review selects up to four passages by literal query matches, or the first sections when no query is given. Purpose-specific provisional questions are labeled a checklist, not findings, company policy or a completed semantic review. Partial reading and zero matches never establish completeness or absence. No statement establishes a signature, deposit, title clearance or action authority. No model/provider call is made by these retrieval services. Configured text models can use the retrieved content as data; more capable paid autonomous reasoning remains subject to C6 admission.

The local command assistant supports exact document titles/IDs and one current document follow-up. Ambiguous or corrected context requires fresh selection. SMS pronouns require an accepted/delivered reply receipt before the incoming request. Explicit “review document … as a saved job” creates a zero-fictional-cost `review_source_document` step; it retrieves the same cited passages/checklist. It is the sixteenth composable work capability, distinct from the sixteen specialist registrations. It neither changes nor shares files. Document links from Agent and saved work open the exact source on desktop and native.

Current document/library references protect stored conversation/tool results, model-context snapshots, derived-work provenance, pending work and saved outputs. Corrections, withdrawal, lost linked-source access or entitlement invalidate current use; no fallback revives an old revision. Original private history remains subject to its existing access rules. Live voice excludes these tools and their derived history; reviewed dictation uses the typed path. Broader semantic analysis/comparison, OCR/other formats, native picking/original handling and actual attachment transfer remain open.

Repeated inherited source checks reuse results only within one synchronous SQLite read snapshot; the cache is actor/reference-scoped and cleared even on errors. Subsequent reads and mutations always revalidate. Proactive source checks retrieve only the referenced topic, avoiding repeated unrelated inbox/transaction reconstruction in accumulated conversations.


## Current roadmap Phase 2 — transaction next-action review

`transaction-follow-through-v3` reviews the independent employee reports without advancing a deal. It exposes reported/unreported milestones, sourced open issues ordered by due date, overdue counts, a missed closing target and potentially inconsistent dates/history. Current-source failures come first; inconsistent reports and issues require reconciliation rather than invented completion. A clearance report with unresolved issues asks whether those issues affect clearance or are separate follow-ups. The dependency checks are provisional review questions, not universal legal ordering rules.

After title opening, guidance asks for actual clearance, then actual signing, funding and closing reports as applicable. Cash/financed title-recipient rules remain unchanged. All-seven-reported remains unverified. The method revision joins the existing source/day fingerprint, retiring obsolete preparations and derived advice. Current desktop/native details, typed Copilot and saved work share the same next action; historical versions show historical reports only. No new schema, source authority, email delivery or milestone-writing model tool was added.

The next-action review now names only the missing agreement or earnest-money report, preserves the report already recorded, and distinguishes a missing supporting source from an unreported event. After title opening, it names the recorded closing attorney and contact source when available. Issue guidance retains the exact issue/source, explains overdue, due-today, undated or after-closing targets, asks for an actual responsible owner rather than inventing one, and retains a missed/today closing target alongside the issue. Resolved issues never become pending work again. Changed/withdrawn sources and inconsistent reports still take precedence. Method v3 changes current preparation/history/work fingerprints, not immutable reports, milestone outcomes or original delivery receipts. Free functional variations are separate from actual-model document judgment.
